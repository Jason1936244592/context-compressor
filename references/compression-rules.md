# 压缩规则详情

本文档详细说明 Context Compressor 的压缩规则和判断逻辑。

---

## 📊 分层压缩策略

### Level 1: 最近对话（完整保留）

| 范围 | 保留比例 | 说明 |
|------|----------|------|
| 最近 10-20 轮 | 100% | 完整保留，不做任何修改 |

**原因**：最近对话最可能被引用，保持完整性确保上下文连贯。

---

### Level 2: 中间对话（精简版）

| 范围 | 保留比例 | 处理方式 |
|------|----------|----------|
| 10-50 轮前 | 40-50% | 保留关键内容，删除冗余 |

**精简策略**：
- ✅ 保留：代码块、配置、关键决策
- ⚠️ 精简：长段解释、推理过程
- ❌ 删除：寒暄、重复确认

---

### Level 3: 早期对话（摘要版）

| 范围 | 保留比例 | 处理方式 |
|------|----------|----------|
| 50+ 轮前 | 10-20% | 生成结构化摘要 |

**摘要内容**：
```markdown
## 对话摘要

### 用户偏好
- 记录的用户偏好...

### 关键决策
- 重要决定点...

### 已完成任务
- [x] 任务列表...

### 待办事项
- [ ] 未完成的任务...

### 重要代码/配置
- 引用或摘要...
```

---

## 🎯 内容优先级判断

### P0: 必须保留

| 类型 | 识别关键词 | 示例 |
|------|-----------|------|
| **用户强调** | "记住这个"、"很重要"、"别忘了" | "记住这个配置，后面还要用" |
| **代码块** | \`\`\` 代码块标记 | 完整的代码文件 |
| **配置变更** | "config"、"设置"、"enable" | "已启用自动备份功能" |
| **关键决策** | "决定"、"结论"、"最终" | "最终决定使用方案 A" |
| **待办事项** | "待办"、"todo"、"稍后" | "稍后需要测试这个功能" |
| **用户偏好** | "我喜欢"、"总是"、"偏好" | "我更喜欢简洁的输出" |

---

### P1: 可以压缩

| 类型 | 压缩方式 | 说明 |
|------|----------|------|
| **推理过程** | 摘要为 1-2 句 | "经过分析，得出以下结论..." |
| **工具输出** | 保留关键部分 | 只保留错误信息或关键数据 |
| **长段解释** | 提取要点 | 保留核心观点，删除举例 |
| **多轮确认** | 合并为 1 条 | 多次确认合并为"已确认" |

---

### P2: 可以删除

| 类型 | 识别特征 | 示例 |
|------|----------|------|
| **寒暄问候** | "你好"、"谢谢"、"再见" | "早上好！有什么可以帮你？" |
| **试错过程** | "让我试试"、"不对"、"重来" | "让我试试这个方法...不对，换个方式" |
| **重复内容** | 与前文相似度>80% | 重复的解释或确认 |
| **已解决错误** | "已修复"、"解决了" | 详细的错误堆栈（已解决的） |
| **系统消息** | 部分工具调用详情 | 完整的 API 响应（可摘要） |

## 🔍 智能识别规则

### 代码块识别

```python
def is_code_block(content):
    return "```" in content or (
        content.count("\n    ") > 3 and  # 缩进代码
        any(kw in content for kw in ["def ", "class ", "import ", "function "])
    )
```

### 配置识别

```python
def is_config_change(content):
    config_keywords = [
        "config", "配置", "设置", "settings",
        "enable", "disable", "开启", "关闭",
        "true", "false", "on", "off"
    ]
    return any(kw in content.lower() for kw in config_keywords)
```

### 关键时刻识别

```python
def is_key_moment(content):
    key_phrases = [
        "重要的是", "关键是", "记住",
        "决定", "结论", "最终",
        "必须", "一定", "务必"
    ]
    return any(phrase in content for phrase in key_phrases)
```

## 📋 压缩质量检查清单

### 压缩前检查

- [ ] 已备份完整对话
- [ ] 已识别所有 P0 内容
- [ ] 已标记代码块和配置
- [ ] 已提取待办事项

### 压缩后检查

- [ ] 最近 20 轮完整保留
- [ ] 所有代码块可访问
- [ ] 配置信息完整
- [ ] 待办事项清晰
- [ ] 上下文连贯
- [ ] 压缩比例达标（60-80%）

### 用户确认项

- [ ] 展示压缩报告
- [ ] 说明保留内容
- [ ] 说明删除内容
- [ ] 提供备份位置
- [ ] 说明恢复方法

## ⚠️ 特殊情况处理

### 情况 1：代码开发会话

**策略**：更保守的压缩

- 保留所有代码块的完整版本
- 保留 bug 修复过程（可能有参考价值）
- 保留测试用例

### 情况 2：问题排查会话

**策略**：保留完整排查链

- 保留错误信息
- 保留排查步骤
- 保留解决方案

### 情况 3：创意讨论会话

**策略**：保留创意要点

- 保留所有创意点子
- 压缩讨论过程
- 保留最终方案

### 情况 4：学习教学会话

**策略**：不建议压缩

- 学习过程本身有价值
- 建议归档而非压缩
- 或仅压缩寒暄部分

## 📊 压缩效果评估

### 评估指标

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| **压缩率** | (压缩前 - 压缩后) / 压缩前 | 60-80% |
| **信息保留率** | P0 内容保留数 / P0 内容总数 | 100% |
| **上下文连贯性** | 人工评分 1-5 | ≥4 |
| **恢复成功率** | 成功恢复次数 / 总恢复次数 | 100% |

### 质量反馈循环

```
压缩 → 用户反馈 → 调整规则 → 再压缩
```

记录用户对压缩结果的反馈，持续优化压缩规则。

## 🔧 自定义规则

### 添加保留关键词

```markdown
# 在 compress.py 中添加
CUSTOM_KEEP_KEYWORDS = [
    "你的关键词",
    "自定义短语"
]
```

### 添加删除规则

```markdown
# 在 compress.py 中添加
CUSTOM_SKIP_PATTERNS = [
    r"正则表达式模式",
    "匹配即删除的文本"
]
```

### 调整压缩比例

```markdown
# 在 compress.py 中修改
self.target_ratio = 0.6  # 0.5=更激进，0.8=更保守
```
